# دليل التثبيت العربي — MfgSystem 1.50.72

## التثبيت الأول بنقرة واحدة

1. نزّل ZIP الفرع الحالي واستخرجه إلى مجلد جديد، مثلاً `D:\MfgSystem_1.50.72`. لا تستخرج الملفات فوق مجلد DateERP أو أي تثبيت سابق.
2. من **جذر المجلد المستخرج** انقر بزر الفأرة الأيمن على `INSTALL-AND-RUN.bat` ثم **تشغيل كمسؤول**، ووافق على نافذة UAC.
3. يفحص المثبّت وجود .NET 8 SDK. إذا لم يجده، يحاول تنزيله وتثبيته؛ يمكن تجهيز `dotnet-sdk-8-win-x64.exe` بجانب المثبّت للاستخدام دون تنزيل SDK.
4. يستعيد المثبّت حزم NuGet، وينشر نسخة Windows x64 ذاتية التشغيل إلى `Application_1.50.72`، ثم ينشئ اختصار سطح مكتب ويشغّل `MfgSystem.exe`.

> عند التحضير عبر هاتف أو جهاز متصل، يمكن تنزيل مثبت SDK الرسمي x64 من [رابط .NET 8](https://aka.ms/dotnet/8.0/dotnet-sdk-win-x64.exe) ونسخه بجوار المثبّت باسم `dotnet-sdk-8-win-x64.exe`. تنزيل الحزم واستعادتها قد يحتاجان إلى إنترنت أو إلى مخزن NuGet محلي مكتمل؛ وجود ملف SDK وحده لا يضمن توافر الحزم دون اتصال.

## قاعدة البيانات والبيانات السابقة

- في تشغيل MfgSystem الأول، إذا لم يوجد إعداد محلي، يختار التطبيق الوضع المحلي ويُنشئ SQLite باسم `mfgsystem_local.db` داخل `%LocalAppData%\MfgSystem`.
- الدخول الأولي: المستخدم `admin` وكلمة المرور `Admin@123`؛ يفرض النظام تغييرها فور الدخول الأول، ولا ينبغي إبقاؤها في الاستخدام الإنتاجي.
- ملفات الإعداد والسجلات والثيمات والمسودات تحفظ تحت `%LocalAppData%\MfgSystem`. نسخ ما قبل ترحيل SQL (عند استخدام SQL Server) في `Documents\MfgSystem\Backups`.
- شاشة النسخ الاحتياطي داخل البرنامج مخصصة لـ SQL Server؛ لا تستخدمها مع SQLite المحلي. تُحفظ نسخ SQL في مسار يستطيع خادم SQL الكتابة إليه.
- لا يقرأ المثبّت إعدادات DateERP القديمة أو يهاجرها، ولا يحذف أو يستبدل قاعدة بيانات أو ملفات مستخدم قديمة. لا تشغّل التحديث فوق مجلد نسخة سابقة.
- إذا سبق تشغيل MfgSystem نفسه على الجهاز، فسيحافظ المثبّت على إعداداته وبياناته الموجودة؛ لا يحذفها بغرض فرض قاعدة جديدة. استخدم حساب Windows جديداً/ملف مستخدم جديداً عند الحاجة إلى مساحة مستخدم مستقلة تماماً.

## التشغيل اليومي

- شغّل اختصار **MfgSystem 1.50.72** على سطح المكتب.
- أو شغّل `Installer\RUN-SYSTEM.bat` من داخل جذر الحزمة. إذا لم تكن النسخة المنشورة موجودة، يستدعي المثبّت الرئيسي.
- ملفات النشر داخل `Application_1.50.72` قابلة لإعادة البناء من المصدر؛ لا تنقل ملفات هذا المجلد إلى تثبيت DateERP سابق.

## SQL Server متعدد المستخدمين (اختياري)

التثبيت بضغطة واحدة يستخدم SQLite محلياً ولا يثبت SQL Server. للتحويل لاحقاً إلى اتصال مركزي:

1. ثبّت SQL Server وأدوات إدارته يدوياً على الخادم، وأنشئ/جهّز قاعدة مستقلة باسم `MfgSystemDB`.
2. يمكن استخدام `Installer\server\إعداد_قاعدة_البيانات.sql` لإعداد قاعدة `MfgSystemDB` الجديدة. السكربت لا يحذف ولا يعيد إنشاء قاعدة موجودة؛ راجعه قبل التنفيذ.
3. افتح إعداد اتصال قاعدة البيانات في التطبيق، وأدخل اسم الخادم/الـ instance والمصادقة، ثم اختبر الاتصال قبل الحفظ. لا تستخدم قاعدة `DateFactory` للنسخ القديمة.
4. النسخ التلقائي عبر SQL Agent اختياري؛ راجع `Installer\server\إعداد_النسخ_الاحتياطي.sql`. SQL Server Express لا يتضمن SQL Server Agent.

## ما لا يقوم به المثبّت

- لا يثبت Visual Studio أو SQL Server أو SSMS.
- لا يحذف قواعد بيانات، ولا يستبدل مجلدات DateERP القديمة.
- لا يبني الحزمة داخل المستودع؛ مخرجات النشر تذهب إلى مجلد الإصدار `Application_1.50.72`.

## حدود التحقق

أُعد هذا الدليل والملفات في بيئة Linux. لم يُشغّل `INSTALL-AND-RUN.bat` أو أوامر CMD/PowerShell، ولم يُنفّذ بناء .NET أو اختبار WPF على Windows. يجب تجربة التثبيت على جهاز Windows نظيف قبل اعتماده للإنتاج.
