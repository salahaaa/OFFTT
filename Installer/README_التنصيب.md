# دليل التنصيب — نظام التصنيع MfgSystem (1.50.67)

## أهم بند: الانفصال التام عن نسخ DateERP القديمة

| المورد | نسخ DateERP القديمة | MfgSystem 1.50.67 | التعارض؟ |
|---|---|---|---|
| البرنامج التنفيذي | `DateERP.exe` | **`MfgSystem.exe`** | لا |
| مجلد البيانات والإعدادات والسجلات | `%LocalAppData%\DateERP_15021` | **`%LocalAppData%\MfgSystem`** | لا |
| قاعدة البيانات | `DateFactory_15021` | **`MfgSystemDB`** (تُنشأ تلقائيًا) | لا |
| مجلد التنصيب | `C:\Program Files\DateERP` | `C:\Program Files\MfgSystem` أو `%LocalAppData%\Programs\MfgSystem` | لا |

نسخك القديمة تبقى تعمل كما هي — لا يلمس النظام الجديد بياناتها ولا قواعدها.

---

## المتطلبات

- ويندوز 10/11 — **64 بت**
- **لا يحتاج تثبيت .NET** — الحزمة مكتفية ذاتياً (self-contained)
- **لا يحتاج صلاحيات مسؤول** — المثبّت يختبر الصلاحيات:
  - مع صلاحيات → `C:\Program Files\MfgSystem`
  - بدون → `%LocalAppData%\Programs\MfgSystem` (بلا أي نافذة UAC)
- SQL Server **اختياري**: إن وُجد أي محرك SQL محلي (مثل `.\SQLEXPRESS` أو `.\SQLEXPRESS01`)
  يكتشفه النظام تلقائيًا في أول تشغيل وينشئ قاعدة `MfgSystemDB` عليه؛
  وإن لم يوجد يعمل بوضع محلي (SQLite) فورًا ويمكنك الربط بالخادم لاحقًا.

## خطوات التنصيب — نقرة واحدة

1. انسخ مجلد `MfgSystem_Publish` (أو استخرج `MfgSystem_FULL.zip`) إلى أي جهاز.
2. انقر **`2-تنصيب.bat`** نقرة مزدوجة — لا حاجة لـ«تشغيل كمسؤول».
3. راقب الخطوات:
   `[1/6]` سلامة الحزمة (SHA256) ← `[2/6]` اختيار المجلد ← `[3/6]` مجلد البيانات ←
   `[4/6]` النسخ ← `[5/6]` الاختصارات ← `[6/6]` التشغيل 🎉
4. فشل شيء؟ أصلح سبب `[ERROR]` ثم **أعد نفس الملف** — المكتمل يُتخطى.

## أول تشغيل — ماذا يحدث؟

1. نافذة البداية (Splash) ثم فحص الإعداد تلقائيًا.
2. **`AutoDbResolver`**: يجرب الخادم المضبوط، ثم يكتشف كل نسخ SQL Server المحلية من سجل ويندوز
   (بما فيها `.\SQLEXPRESS01`) ويختبرها — وعند النجاح يضبط الإعداد على الصحيحة **تلقائيًا**.
3. إن لم يوجد أي محرك: يعرض التشغيل بالوضع المحلي المدمج (SQLite في مجلد بيانات هذه النسخة).
4. قاعدة فارغة؟ تُنشأ الجداول والبيانات الأساسية (مستخدم `admin` …) تلقائيًا بلا سؤال.
5. تغيير الاتصال لاحقًا: **معلومات النظام ← تعديل الاتصال**.

## البناء من المصدر (جهاز المطوّر — ويندوز فقط)

```bat
:: يتطلب .NET 8 SDK على ويندوز (بناء WPF غير ممكن على Linux)
Installer\1-بناء_الحزمة.bat
```

يفعل السكربت: استعادة ← اختبارات (يتوقف عند الفشل) ← نشر `win-x64` مكتفٍ ذاتيًا ←
نسخ أدوات التنصيب ← توليد `VERSION.txt` و`SHA256.txt` من `MfgSystem.exe` ← ضغط `MfgSystem_FULL.zip`.

> 💡 CI على GitHub يبني وينشر ويعيد حزمة جاهزة كـ artifact عند كل دفع على ويندوز
> (الملف الجاهز: `CI/CI_WORKFLOW_READY.yml` مع تعليمات التفعيل في `CI/README_AR.md` —
> لم يُفعَّل بعد لأنه يتطلب صلاحية `workflows` غير متوفرة لأداة النشر).

## إلغاء التنصيب

`إلغاء_التنصيب.bat` من مجلد التنصيب: يزيل التطبيق والاختصارات و**يحفظ البيانات** افتراضيًا
(الحذف فقط بتأكيد صريح). لا يلمس أي نسخة DateERP قديمة.

## فحص الجهاز قبل التنصيب (اختياري)

`فحص_المتطلبات.bat` — نظام التشغيل، المعمارية، الذاكرة، القرص، والمحركات المحلية (معلوماتي).

## حل المشكلات السريع

| المشكلة | الحل |
|---|---|
| «MfgSystem.exe not found next to this script» | استخرج الحزمة كاملة وشغّل السكربت من داخل مجلدها |
| «SHA256 mismatch» | الحزمة تالفة — أعد التنزيل/النسخ من المصدر السليم |
| «Copy failed» | أغلق النافذة المفتوحة على المجلد، أو أعد كمسؤول |
| التطبيق لا يتصل بالقاعدة | يكتشف النظام المحركات تلقائيًا؛ إن لم ينجح اقبل الوضع المحلي ثم اربط الخادم من «معلومات النظام» |
| أريد قاعدة على خادم شبكي | «معلومات النظام ← تعديل الاتصال» — اسم الخادم: `SERVER01` أو `SERVER01\SQLEXPRESS` أو IP (ولا تستخدم `localhost` على الأجهزة العميلة) |
| السجلات | `%LocalAppData%\MfgSystem\logs\` + أثر الإقلاع بجانب `MfgSystem.exe` |

## البصمة

`SHA256.txt` مضمّن في الحزمة ويتحقق منه المثبّت تلقائيًا. للتوليد يدويًا:

```bat
powershell -NoProfile -Command "Get-FileHash -Algorithm SHA256 MfgSystem.exe | Select-Object -ExpandProperty Hash"
```
