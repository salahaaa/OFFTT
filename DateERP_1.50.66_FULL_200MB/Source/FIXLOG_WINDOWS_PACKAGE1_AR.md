# تقرير حزمة Windows — 1.50.4

## التسليم

حزمة تشغيل فعلية `DateERP_1.50.4_win-x64.zip` تحتوي `DateERP.exe` ومكتبات التطبيق ومحرك .NET/WPF 8.0.30 واعتمادات SQLite وSQL Client الأصلية المخصصة لـ x64، ودليل التشغيل، وبيان SHA256، وفحص WPF دون قاعدة بيانات. ليست مجرد مصدر، وليست مثبّت MSI/Setup.exe أو حزمة اختُبرت على Windows فعلياً.

الإصدار **1.50.4** والختم **2026-09-09 WindowsPackage1**. منطق نعم/لا وحتى تاريخ وترحيل 1.50.3 لم يتغير. لا أعمدة أو جداول جديدة في هذا التحديث.

## لماذا تغير رقم الإصدار؟

أول نشر بـ `-r win-x64 --self-contained true` توقف بسبب تدقيق NuGet: الرسم الانتقالي لهذا الهدف حلّ `System.Private.Uri/4.3.0` عبر `runtime.any.System.Runtime/4.3.0`. هذه نتيجة خاصة برسم النشر، لا تناقض مع تدقيق البناء العام السابق الذي لم يظهر هذا الاعتماد فيه.

لم يُعطّل التدقيق ولم تُكبت التحذيرات. أضيف مرجع صريح **System.Private.Uri 4.3.2** في مشروع Infrastructure، وأعيد النشر بنجاح. مرجع التصحيح: https://github.com/advisories/GHSA-xhfc-gr8f-ffwc . تدقيق الهدف Windows بعد التصحيح لم يعد يظهر اعتمادات ذات ثغرات معروفة حسب المصادر الحالية. فحص ملف `System.Private.Uri.dll` المنشور أكد أنه ملف محرك .NET **8.0.30**، لا DLL القديم 4.3.0.

أضيف اختباران: حارس لنسخة الاعتماد المصححة، والتحقق من بقاء Uri على محرك حديث مع مسار عربي صحيح.

## النشر

```bash
dotnet publish src/DatesErp.Desktop/DatesErp.Desktop.csproj \
  -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=false -p:PublishTrimmed=false \
  -p:PublishReadyToRun=false -warnaserror -o <output>
```

استُخدم SDK 8.0.424. أبقيت الحزمة متعددة الملفات دون trimming لتجنب إفساد تحميل WPF/EF بالانعكاس. محركا Microsoft.NETCore.App وMicrosoft.WindowsDesktop.App المضمنان هما 8.0.30. ملفات التطبيق لا تحتاج .NET مثبتاً خارجها، لكن نظام Windows المتوافق وقاعدة SQL Server إن استُخدمت ليسا جزءاً من الحزمة.

أداة `ReceivingWpfSmoke` نُشرت أيضاً لـ win-x64 مكتفية ذاتياً. أضيفت ملفاتها الخمسة إلى مجلد التطبيق، وتحقق تطابق كل ملفاتها المشتركة مع نشر التطبيق. الموارد اللغوية الإضافية غير اللازمة للأداة لم تُضف؛ تستخدم النسخة نفس الموارد العربية/الافتراضية للحزمة.

## السلامة والتثبيت

- اختير التشغيل من مجلد جديد؛ لا سكربت يحذف تثبيتاً قديماً ولا حاجة لصلاحيات مدير لمجرد فك الحزمة في مجلد المستخدم.
- لم تُضمّن أداة التنصيب القديمة التي تحذف مجلد التطبيق قبل النسخ.
- الحزمة لا تتضمن قاعدة مستخدم أو ملف إعداد اتصال أو أسراراً. مع ذلك، التطبيق يقرأ إعداد الحساب الموجود وقد يرحّل قاعدة البيانات عند الإقلاع؛ **مجلد جديد لا يعني قاعدة معزولة**.
- `Verify-Release.ps1` يفحص الملفات قراءةً فقط ولا يغير سياسة PowerShell أو قاعدة البيانات. SHA256 ليس توقيع ناشر؛ ملفات DateERP غير موقعة بشهادة Authenticode.
- `Check-WPF.cmd` يشغّل 12 فحصاً بالقوالب والثيم الفعليين دون فتح قاعدة بيانات، ويحفظ سجلاً في TEMP. تشغيله على جهاز المستخدم خطوة قبول مطلوبة، لا نتيجة سبق ادعاء نجاحها هنا.
- التشغيل على Windows وقاعدة اختبارية يسبق تحديث جميع العملاء. دليل `Documentation/WINDOWS_RELEASE_1.50.4_AR.md` يشرح النسخ الاحتياطي والاتصال والتحقق من الإصدار والاستعادة.
