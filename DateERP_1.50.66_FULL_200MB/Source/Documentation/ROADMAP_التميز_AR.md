# خارطة التميّز — ما يُضاف إلى نظام DateERP ليصبح نظاماً ممتازاً

> مراجعة مهنية مبنية على قراءة الكود الفعلي (النطاق، الخدمات، شاشة الخطط، محرك التقارير، طبقة القاعدة، حرّاس CI)، لا على قائمة عامة.

---

## ١) ما هو قوي فعلاً (لا تُصلحه)

| المجال | الحالة |
|---|---|
| فصل الطبقات | `Core` / `Application` / `Infrastructure` / `Desktop` — نظيف وواضح |
| دورة العمل | من الاستلام والمعالجة حتى التسليم والفوترة مغطاة فعلياً بنماذج حقيقية |
| حماية الجودة | 788 اختباراً + حرّاس بنيوية (RTL، معالجات فارغة، سياسة `double`) — نادر في مشاريع مماثلة |
| التزامن | `rowversion` + سجل تدقيق + أرقام مستندات مركزية |
| التقارير | 15+ تقريراً بمحرك واحد، تصدير PDF/Excel، وربط المستند بالصف |
| سياسة الوحدات | `UiFormat` + `ReportUnits` — تعاقد واحد للأرقام والوحدات بدل اجتهاد كل شاشة |

**الخلاصة:** الأساس سليم. التوصيات التالية **إضافات قيمة** لا إصلاح عيوب.

## ٢) الموجة الأولى — أعلى أثر بأقل مخاطرة (٤–٨ أسابيع)

### ٢.١ الباركود/QR على الدفعة والكرتون ⭐ الأعلى أثراً
الدفعات تُدار اليوم بأرقام نصية. في مصانع التمور الباركود هو الفرق بين نظام يُستعمل ونظام يُتجاوَز.
- ملصق لكل **دفعة خام** (LOT) و**كرتون تام** يُطبع عند الإقفال.
- قارئ عند: الاستلام، الصرف للإنتاج، الإقفال، التسليم.
- يقتل أكبر مصدر خطأ بشري: إدخال رقم دفعة/صنف خاطئ.
- **الأثر:** مرتفع جداً · **الجهد:** متوسط · **يعتمد على:** مكوّن طباعة الملصقات (موجود: محرك الطباعة).

### ٢.٢ التكلفة الفعلية للوحدة (Costing Engine) ⭐ الأعلى قيمة مالية
النظام يتابع الكميات بدقة لكنه لا يجيب: «كم كلّفني كرتون تمر سكري لعميل معيّن؟»
- كلفة الكرتون = خام (من فاتورة الشحنة) + عمالة (ساعات الوردية × أجر) + مواد مساعدة + خام تالف/فاقد مخصّصاً + دفعة الطاقة.
- تقارير هامش لكل عميل/صنف/أمر، ومقارنة المخطط بالفعلي.
- البذرة موجودة (`DefaultCost`, `LastCost`, `HourlyProductionRate`) لكنها غير موصولة بمحرك كلفة.
- **الأثر:** مرتفع جداً (قرارات تسعير) · **الجهد:** مرتفع.

### ٢.٣ إغلاق الفترة المحاسبية (Period Close)
لا يوجد ما يمنع تعديل مستند معتمد من الشهر الماضي بأثر رجعي.
- إقفال شهر: يمنع تعديل/حذف أي مستند معتمد قبل تاريخ الإقفال دون صلاحية + سبب مُسجَّل.
- **الأثر:** مرتفع (سلامة التقارير) · **الجهد:** منخفض–متوسط.

### ٢.٤ سجل تدقيق على مستوى الحقل (Field-level Audit)
حالياً يُسجَّل اسم العملية غالباً. المطلوب: «من غيّر كمية البند من 1,000 إلى 900 ومتى».
- **الأثر:** مرتفع (مساءلة ونزاعات) · **الجهد:** منخفض–متوسط.

## ٣) الموجة الثانية — تشغيلية (٨–١٦ أسبوعاً)

### ٣.١ واجهة برمجية + عميل ميداني (API + Web/Mobile)
التطبيق WPF مكتبي فقط. للإدارة من الفرع/المخزن/الهاتف تحتاج طبقة خدمة.
- **ASP.NET Core + OpenAPI** فوق نفس `Application services` (مصمّمة أصلاً لتكون قابلة للحقن).
- عميل ويب/هاتف للاستعلام والاعتماد والمهام، لا للإدخال الكامل.
- **الأثر:** مرتفع جداً (توسّع) · **الجهد:** مرتفع.

### ٣.٢ الوضع غير المتصل + مزامنة (Offline-first)
انقطاع الكهرباء/الشبكة واقع تشغيلي. SQLite المحلي موجود فعلاً — يُبنى عليه:
- طابور عمليات محلي → مزامنة عند العودة، مع **بناء أولوية** عند التعارض (المستند المعتمد يفوز، والبقية تُصعَّد للمراجعة).
- **الأثر:** مرتفع جداً · **الجهد:** مرتفع.

### ٣.٣ تكامل الميزان (Scale Integration)
قراءة الوزن مباشرة من ميزان الاستلام/الإقفال بدل إدخال يدوي.
- عبر منفذ تسلسلي/TCP وبروتوكول الميزان، مع حارس قراءة مستقرة.
- **الأثر:** مرتفع (الوزن = المال) · **الجهد:** متوسط.

### ٣.٤ تكامل التقاط الصور في الجودة
مرفق صورة لكل فحص/شحنة (من كاميرا الجهاز أو ملف)، تُخزَّن مربوطة بالمستند وتظهر في شهادة الجودة.
- **الأثر:** متوسط–مرتفع (إثبات ونزاعات) · **الجهد:** متوسط.

### ٣.٥ شهادة تحليل لكل دفعة (CoA) + محاكاة استدعاء
- توليد شهادة تحليل بترويسة الشركة من بيانات الفحص المخبري (رطوبة/سكريات/شوائب) تُرسل للعميل.
- زر واحد: «تتبع هذه الدفعة رجوعاً للأمام» يُخرج كل لوط/عرض/عميل تأثّر — للاستدعاء.
- محرك التتبع موجود (`TraceabilityService`) — الفجوة في العرض والمستند لا في البيانات.

## ٤) الموجة الثالثة — النضج (استمرارية)

| البند | لماذا |
|---|---|
| **هجرات EF رسمية** بدل `SchemaMigrator` | ترقية آمنة وقابلة للتراجع بين إصدارات |
| **مهام خلفية** (Hosted Service) | إعادة حساب أرصدة/تقارير ثقيلة ليلاً، نسخ احتياطي، تنبيهات |
| **اختبار استرجاع النسخة الاحتياطية آلياً** | نسخة لم تُجرَّب استرجاعها ليست نسخة |
| **مراقبة وتشخيص** | تسجيل مُهيكل + Health checks + توليد «حزمة دعم» عند العطل بضغطة |
| **صلاحيات على مستوى الحقل** | إخفاء التكلفة/الأرباح عن من لا يحتاجها |
| **2FA وسياسة جلسات** | لأن النظام يحمل بيانات تجارية حساسة |
| **توسيع الشكل الموحد على كل الشاشات** | بدأنا في التقارير؛ نفس التعاقد البصري للشاشات |
| **إدخال جماعي/لصق من Excel + تراجع (Undo)** | يوفّر ساعات إدخال يومياً |

## ٥) الترتيب المقترح

```
الموجة 1: التكلفة → إقفال الفترة → تدقيق الحقل → الباركود
الموجة 2: الميزان → الصور في الجودة → CoA/الاستدعاء → API + عميل ميداني
الموجة 3: Offline-first → هجرات EF → مهام خلفية → مراقبة → صلاحيات الحقل
```

**لو اخترت بنداً واحداً:** **التكلفة الفعلية للوحدة**. هي التي تحوّل النظام من «مسجّل عمليات ممتاز» إلى «أداة قرار وربح» — وكل البيانات اللازمة لها موجودة، والفجوة في محرك الحساب والعرض فقط.

**معيار النجاح:** لكل بند يُضاف، يجب أن يُثبَت باختبار آلي (على نمط `SourceDrawProof` والـ788 الحالية) — لا ميزة بلا إثبات.
