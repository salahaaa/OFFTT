# تشغيل حزمة Windows — DateERP 1.50.4

**الختم:** `2026-09-09 WindowsPackage1`
**نوع الحزمة:** نسخة تشغيل من مجلد، Windows x64، مكتفية ذاتياً بـ .NET 8.0.30 وWPF. ليست MSI أو Setup.exe، ولا يلزم تثبيت .NET أو أدوات التطوير لتشغيلها.

> **تنبيه قبل التشغيل:** التطبيق يستخدم الإعداد الموجود في `%LocalAppData%\DateERP\config.json` تلقائياً، وقد يحدّث مخطط قاعدة البيانات المتصل بها عند الإقلاع. لا تفتحه على قاعدة العمل قبل أخذ نسخة احتياطية واختبار نسخة من البيانات. فك الملفات في مجلد جديد لا يعزل قاعدة البيانات وحده.

## 1. المتطلبات

- Windows 10/11 بإصدار 64 بت، مع تحديثات النظام المناسبة. هذه ليست حزمة x86 أو ARM64 أصلية.
- مساحة كافية لفك الحزمة؛ ملفات التشغيل نحو 171 MiB قبل ضغط ZIP.
- إذا استُخدمت قاعدة SQL Server مركزية: الخادم وقاعدة البيانات وصلاحيات الاتصال واتصال الشبكة مطلوبة بشكل منفصل. الحزمة لا تثبّت SQL Server.
- أول تشغيل بحساب Windows لا يملك إعداداً سابقاً ينشئ وضعاً محلياً وقاعدة SQLite. لا تدخل بيانات العمل في قاعدة تجربة بالخطأ.

## 2. فك الحزمة والتحقق الآمن

1. نزّل ZIP وفكّه **كاملاً** إلى مجلد محلي جديد، مثل `C:\Users\اسمك\Apps\DateERP-1.50.4`. لا تفتح EXE من داخل ZIP ولا تنقل EXE وحده.
2. احتفظ بالمجلد القديم ولا تخلط DLLs الإصدارين. لا تتطلب طريقة التشغيل هذه حذف تثبيت سابق أو تشغيل أداة التنصيب القديمة.
3. اختياري: قارن بصمة ZIP بملف `SHA256SUMS.txt` المرافق:

```powershell
Get-FileHash -Algorithm SHA256 "C:\مسار\DateERP_1.50.4_win-x64.zip"
```

4. يوجد داخل الحزمة `release-manifest.json` ببصمات الملفات و`Verify-Release.ps1` لفحصها قراءةً فقط:

```powershell
powershell -NoProfile -File ".\Verify-Release.ps1"
```

إذا منعت سياسة جهازك السكربت، اطلب من مسؤول الجهاز مراجعته؛ لا تعطّل حماية النظام. البصمات تتحقق من سلامة المحتوى، وليست توقيع ناشر موثوقاً. ملفات تطبيق DateERP غير موقعة بشهادة Authenticode؛ قد يظهر تحذير من Windows. لا تتجاوز التحذير دون التحقق من مصدر الحزمة وبصمتها.

## 3. اختبار الواجهة دون فتح قاعدة بيانات

شغّل **`Check-WPF.cmd`**. يستدعي أداة `ReceivingWpfSmoke.exe` المرفقة ويختبر 12 شرطاً باستخدام WPF والثيم وقوالب الإدخال الفعلية، منها:

- القرار فارغ أولاً ووجوب الاختيار الصريح.
- ظهور حتى تاريخ عند نعم، وقبول تاريخ مخصص.
- مسح التاريخ وإخفاؤه عند لا.
- تعطيل التحرير في المستند المعتمد.

الأداة لا تفتح قاعدة بيانات ولا تدخل إلى التطبيق الرئيسي. تحفظ نتيجتها في ملف مؤقت يظهر مساره. إذا لم يظهر `PASS: 12 real WPF checks` أو كان رمز الخروج غير صفر، فلا تحدث بيئة العمل؛ أرسل سجل هذا الفحص.

**هذه الأداة بُنيت ونُشرت هنا، لكنها لم تُشغّل على Windows في بيئة التسليم.** كذلك سكربتات Windows المرفقة لم تُنفذ هنا. نجاحها لديك لا يغني عن اختبار قاعدة البيانات ودورة العمل.

## 4. تشغيل التطبيق

بعد فحص الواجهة وتجهيز قاعدة اختبارية، شغّل **`DateERP.exe`**.

- تحقق من الإصدار **1.50.4** والختم **2026-09-09 WindowsPackage1**.
- بيانات الإعداد والقاعدة المحلية والسجلات ليست داخل مجلد الحزمة؛ توجد في `%LocalAppData%\DateERP`.
- إذا كان الحساب متصلاً بقاعدة العمل بالفعل، استخدم حساب Windows اختبارياً منفصلاً أو جهاز اختبار قبل فتح التطبيق. غيّر الاتصال من **معلومات النظام ← تعديل الاتصال** ليشير إلى نسخة اختبارية، واختبر الاتصال قبل حفظه.
- إعداد اتصال SQL المشفر لا يُفترض أنه قابل للنقل إلى جهاز آخر؛ أعد ضبط الاتصال على كل جهاز بالطريقة المعتمدة.
- للإصدار الحالي، معالجة الاستلام هي **نعم/لا وحتى تاريخ داخل كل صف**، لا علم الصنف ولا نافذة مدد مستقلة. السلوك الوظيفي الموثق في دليل ReceivingInline2 باقٍ؛ اختلاف هذا الإصدار هو حزمة Windows وتحديث اعتماد النشر.

## 5. اختبار القبول على نسخة من البيانات

1. استلام 08/09/2026، المعالجة لا: لا تاريخ محفوظ ولا معالجة بعد الاعتماد.
2. نعم حتى 15/09/2026، ومثال آخر حتى شهر لاحق: يثبت الموعد كما اخترته بلا تحويل إلى مدة ثابتة.
3. سند مختلط لنفس الصنف: نعم بموعدين مختلفين، ولا في صف ثالث.
4. جرّب ترك القرار أو تاريخ نعم فارغاً، أو إدخال نهاية أسبق من الاستلام: يجب رفض الحفظ.
5. استخدم **تاريخاً مستقبلياً فعلاً** للتحقق من الحجز ومنع اعتماد/بدء الإنتاج والصرف المبكر. أمثلة سبتمبر القديمة إذا مضى موعدها تستكمل عند الاعتماد؛ هذا ليس إفراجاً مبكراً.
6. تحقق من تقرير «معالجة بنود الاستلام — نعم/لا وحتى تاريخ» ومن رصيد مخزن الاستلام وWTRT.
7. عند الاستحقاق من بداية اليوم المختار، تتم المتابعة أثناء فتح التطبيق كل 60 ثانية أو عند العملية التالية. عند إغلاق جميع العملاء لا يعمل عامل مستقل.

لا تغيّر ساعة خادم العمل لاختبار المواعيد. استخدم بيئة اختبار معزولة إن احتجت محاكاة الزمن.

## 6. تحديث بيئة العمل

- أوقف جميع العملاء وخذ نسخة احتياطية قابلة للاستعادة. في SQL Server استخدم نسخة قاعدة صحيحة؛ نسخ `config.json` لا ينسخ قاعدة الخادم.
- في SQLite أغلق التطبيق تماماً قبل النسخ؛ احتفظ بملفات القاعدة المصاحبة إن وجدت، ولا تنسخ ملف DB مفتوحاً على أنه نسخة احتياطية مضمونة.
- حدّث جميع الأجهزة معاً إلى المجلد الجديد، ثم بدّل الاختصار إلى `DateERP.exe` الجديد بعد نجاح القبول.
- التطبيق قد يرحّل المخطط تلقائياً. الرجوع إلى EXE قديم وحده ليس خطة استعادة مضمونة؛ احتفظ أيضاً بنسخة قاعدة ما قبل الترقية واتبع خطة مسؤول النظام.
- لا توزّع ملفات القاعدة أو `config.json` أو كلمات المرور ضمن حزمة التطبيق. الحزمة المرفقة لا تحتوي على بيانات مستخدم أو إعداد اتصال جاهز.

## 7. إذا لم يفتح البرنامج

أرسل وصف الخطأ ورقم إصدار Windows ومعماريته، ونتيجة `Check-WPF.cmd`. إن وصل التطبيق إلى الإقلاع، راجع:

- `boot_trace.txt` بجانب `DateERP.exe` إذا كان المجلد قابلاً للكتابة.
- `%LocalAppData%\DateERP\logs`.

راجع السجلات واحذف منها بيانات حساسة قبل مشاركتها. لا ترسل قاعدة العمل أو `config.json` أو كلمات المرور.
