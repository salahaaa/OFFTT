# سجل إصلاحات الجولة B110 — استجابة تقرير الفحص الشامل
**التاريخ:** 2026-09-11 · **النسخة:** 1.50.37 (ما بعد التدقيق) · **المرجع:** `AUDIT_1.50.37_COMPREHENSIVE_AR.md`
**المنهج:** إصلاحات جراحية على الكود القائم مع اختبار لكل إصلاح حيث أمكن. **حدّ معلن:** لم يتوفر .NET SDK في بيئة التنفيذ، فلم يُبنَ الحل محلياً — الاعتماد النهائي يمر عبر دورة CI الكاملة (وهي الآن أوسع: تشمل SQL Server فعلياً).

---

## 1) ما نُفذ — مرتباً بخطورة الملاحظة الأصلية

### 🔴 H1 — حجب حقول الاعتماد من سجل التدقيق
- **الملف:** `AuditSaveChangesInterceptor.cs`
- **التغيير:** لقطة التدقيق (قبل/بعد) تُبنى الآن خصيصةً خصيصةً مع قائمة حجب مركزية (`PasswordHash`/`PasswordSalt`) — لا عبر `ToObject()` الكامل.
- **الملف:** `DbSeeder.cs` — هدف ترقية البيانات المرجعية رُفع إلى **B110**؛ خطوة جديدة `ScrubAuditCredentials` تمسح المفاتيح من سجلات التدقيق التاريخية في كل قاعدة قائمة (مرة واحدة، بميزة علامة `RefDataUpgrade`).
- **الاختبارات:** `AuditCredentialRedactionTests` (3): لا بصمات بعد تصفير كلمة المرور، الحقول الأخرى تبقى مدققة، السجلات التاريخية تُنظف مرة واحدة وبأمان للتكرار.

### 🔴 H2 — `decimal(18,4)` حقيقية على SQL Server
- **الملف:** `DatesErpDbContext.cs` — دقة موحدة 18,4 لكل المزودين؛ **المحوّل النصي أصبح مقيداً بـ SQLite فقط**.
- **الملف:** `SchemaMigrator.cs` — خطوة `RepairDecimalColumns`: كل عمود decimal ما زال نصاً على SQL Server يُحوَّل إلى `decimal(18,4)` عبر عمود مؤقت + `TRY_CAST` + إعادة تسمية، مع تقرير لكل عمود.
- **الاختبارات:** `DecimalStorageParityTests` (3): نوع العمود `decimal(18,4)` بلا محوّل على SQL Server، المحوّل النصي باقٍ على SQLite، وقيم `7.5` تعود كما هي.

### 🔴 H3 — المرحّل: فهارس + شفافية التعبئة
- **الملف:** `SchemaMigrator.cs`
  - `EnsureIndexes`: كل فهرس في النموذج (فريد/عادي/مصفّى) يُتحقق منه بالاسم وبتوقيع الأعمدة ويُنشأ إن غاب — للجداول الجديدة والقائمة على السواء.
  - `SweepNulls`: كل تعبئة فراغات تُعلن الآن في تقرير الترحيل بعدد الصفوف — لا تغيير دلالة صامت.
- **الاختبارات:** `SchemaIndexRepairTests` (2): فهرسان فريدان يُسقطان ويعيدهما الترحيل؛ والتكرار آمن بلا تكرار فهارس.

### 🟠 M4 — مصفوفة SQL Server في الاختبارات وCI
- **الملف الجديد:** `SqlServerProviderTests.cs` — قاعدة فريدة لكل تشغيل (تُنشأ وتُسقط آلياً)، تتفعل بمتغير البيئة `DATESERP_SQL_CONNECTION` وتبقى نجاحاً فارغاً بدونه. تغطي: البذر والدخول على خادم حقيقي، تعارض `rowversion`، التدقيق بلا اعتماد مسرب، أعمدة decimal حقيقية **بترتيب عددي مُثبت** (9.5 قبل 10.25)، وترقيماً متسلسلاً.
- **مهمة CI الجديدة `sqlserver-integration`:** جاهزة في `CI_PENDING_sqlserver-integration-job.yml` (خدمة `mcr.microsoft.com/mssql/server:2022-latest` + فحص جاهزية). **لم تُدفع إلى `.github/workflows/ci.yml`** لأن صلاحية الدفع الحالية لا تشمل تعديل ملفات سير العمل (`workflows`) — أضف محتوى الملف إلى `ci.yml` من حساب يملك الصلاحية ثم ادفعه، وستعمل المهمة فوراً بلا أي تعديل إضافي.

### 🟠 M5 — الترقيم المتسلسل على SQL Server
- **الملف:** `DependencyInjection.cs` (`NumberingService.Next`) — صف المخطط يُقفل `WITH (UPDLOCK, HOLDLOCK)` داخل معاملة المستدعي: جهازان متزامنان يتسلسلان بدل أن يقرآ نفس التسلسل. مسار SQLite بلا تغيير، وإعادة المحاولة عند تعارض القيد الفريد تبقى شبكة الأمان على المزودين.

### 🟠 M6 — إنهاء الكتابة المباشرة من الواجهة
- **الخدمات الجديدة:** `MasterDataService.ToggleByProduct`، `MasterDataService.SaveCompanyInfo`، `PermissionService.CreateCustomRole` — كلها بصلاحية مفروضة وتدقيق ومنع تكرار.
- **الشاشات:** «المجموعات والأصناف» (إضافة/قلب المخارج الثانوية)، «الصلاحيات» (دور جديد)، «معلومات النظام» (بيانات الشركة) — تستدعي الخدمات الآن. لم يبق `SaveChanges` في مشروع الواجهة إلا في `Bootstrapper` (ختم الإقلاع).
- **الحارس البنيوي:** `tools/ci/structural_checks.py` — فحص جديد يرفض أي `SaveChanges` في `DatesErp.Desktop` خارج قائمة السماح، مع اختبارات للحارس نفسه في `test_structural_checks.py`.

### 🟠 M7 — المصدر في المستودع
- فُكّت حزمة `DateERP_1.50.37_FULL_SOURCE.zip` كاملة في جذر المستودع (شجرة `src/tests/tools/audit/Installer/Documentation` + FIXLOGs) وأُخرج الـ ZIP من التتبع — المستودع الآن قابل للمراجعة والـ `blame`، والحزم تُرفق لاحقاً كأصول إصدار.

### 🟡 L5 — تصحيحات توثيق
- مسار سجل الأخطاء الحقيقي `%LocalAppData%` (كان التوثيق يذكر `%ProgramData%`).
- منفذ SQL Browser في دليل التنصيب: 1434 (كان 1444).
- تقرير الإصدار الشبكي الأول وُسم «مؤرشف» مع بيان الوضع الحالي.

## 2) ما لم يُنفذ هذه الجولة — بمبرر صريح

| البند | السبب | المسار المقترح |
|---|---|---|
| **M1 — صفر `async`** | تحويل الخدمات للبرمجة غير المتزامنة يمس كل مسار استدعاء وكل اختبار؛ مشروع مستقل بذاته | خطة تدريجية: الخدمات الأكثر استخداماً أولاً (خطط/تقارير/قوائم) مع مؤشر انشغال |
| **M2 — ترحيل `double` القديم** | 108 حقول كميات/أوزان متغلغلة في الحسابات والاختبارات؛ التحويل الآمن يحتاج اختبارات مالية/مخزنية مخصصة | مشروع ترحيل مستقل — حارس «لا `double` جديداً» قائم ومُثبت |
| **M3 — تخزين التواقيت UTC** | يمس 116 موضعاً ونوافذ القفل والتفويض والعرض المحلي | تخزين UTC + عرض محلي في موجة واحدة مع اختبارات النوافذ الزمنية |
| **M8 — مسارات النسخ الاحتياطي** | تحتاج بيئة خادم فعلية للتحقق (سلوكها معلوم وموثق في `SECURITY_UPGRADE_AR.md`) | إعادة تصميم بمسار خادم صريح عند توفر بيئة اختبار خادم |
| **التحقق بالبناء** | لا .NET SDK ولا وصول NuGet في بيئة التنفيذ | **إلزامي:** دورة CI كاملة قبل أي نشر (المهمة الجديدة تضيف تغطية SQL Server) |
