## 3. ترحيل قاعدة البيانات والسندات القديمة

- **الترحيل:** لا سكربت يدوي. عند أول إقلاع للنسخة، `SchemaMigrator` يكتشف غياب العمود `CustomerDeliveries.WarehouseId` وينفّذ `ALTER TABLE [CustomerDeliveries] ADD [WarehouseId] int NULL`. لا يُلمس أي صف قائم.
- **القيمة المتوافقة للسندات القديمة:** `NULL` = «سند سابق للعمود». لا يُملأ تلقائياً بقيمة مخمّنة.
- **سياسة التوافق عند الاستخدام:**
  - مسودة قديمة تُعتمد → تُصرف من WFG (المسار الثابت الوحيد قبل هذا الإصدار) ويُسجَّل `WarehouseId = WFG` لحظة الاعتماد.
  - سند قديم معتمد يُلغى → المخزن = مخزن حركات الصرف المسجلة للسند نفسه (`ReferenceDocNumber = رقم السند` أو `#R…`). إن لم توجد حركات → WFG. إن تعددت المخازن في الحركات → رفض برسالة «يحتاج مراجعة يدوية» (لا نسبة لمخزن بلا دليل).
  - الشاشة تعرض WFG للسند القديم مع تلميح صريح، ولا تحفظ شيئاً حتى يضغط المستخدم حفظ/اعتماد.
- **المسودات القائمة** يمكن تغيير مخزنها بحرية (لا أثر مخزني)؛ **المعتمد** لا يتغير مخزنه إلا بعد إلغاء الاعتماد (الخدمة ترفض + الحقل معطّل في الشاشة).
