# تقرير تجهيز حزمة MfgSystem المستقلة — 1.50.72

**التاريخ:** 2026-10-22
**الفرع:** `arena/01a091dd-offtt`
**الغرض:** مصدر النسخة الحالية مع أداة تثبيت وتشغيل، وقاعدة محلية جديدة منفصلة عن مجلدات DateERP السابقة.

## النتيجة

أُعدّت حزمة مصدر من الفرع الحالي ومثبّت رئيسي `INSTALL-AND-RUN.bat`. في أول تشغيل على ملف مستخدم لا يحوي إعداد MfgSystem سابقاً، يختار التطبيق SQLite وينشئ `%LocalAppData%\MfgSystem\mfgsystem_local.db` ويُهيّئ البيانات الأساسية. الدخول الأولي `admin` / `Admin@123`، مع فرض تغيير كلمة المرور عند أول دخول. لا يقرأ المثبّت إعدادات أو قواعد DateERP القديمة ولا يحذفها أو ينسخ فوقها.

## ما عُدّل

1. **التثبيت والتشغيل:** أُضيف مثبّت ASCII/CRLF من ملف BAT واحد، يطلب صلاحية المسؤول عبر UAC، يتحقق من .NET 8 SDK أو يحاول تثبيته، يستعيد حزم NuGet، وينشر `win-x64` ذاتياً إلى `Application_1.50.72`، ثم ينشئ اختصاراً ويشغّل `MfgSystem.exe`. يوقف المسار عند الفشل ويسجل `BUILD SUCCESS` / `INSTALL SUCCESS` أو `[FAILED]`.
2. **منع لمس المجلدات السابقة:** يرفض المثبّت الجذري ومحدّث المصدر مجلد الأرشيف `D:\DateERP_1.50.20_Full` ومجلده الداخلي `D:\DateERP_1.50.20_Full\DateERP_1.50.20` ومجلد العمل القديم `D:\DateERP_1.50.43_FULL_SOURCE`. لا يقتل التطبيق بالقوة أثناء التحديث؛ يطلب إغلاقه طبيعياً.
3. **هوية بيانات منفصلة:** ملف الإعداد والثيمات والمسودات تحت `%LocalAppData%\MfgSystem`، وسجلات الأخطاء/الإقلاع في مجلد `logs` تحته، والنسخ قبل ترحيل SQL تحت `Documents\MfgSystem\Backups`. أزيل نقل ملف تذكر الدخول من موقع DateERP القديم. ملف إعداد MfgSystem موجود مسبقاً يُحفظ ولا يُمسح لفرض قاعدة جديدة.
4. **قاعدة البيانات:** أول تشغيل نظيف يهيّئ SQLite باسم `mfgsystem_local.db` تلقائياً. لا يُشغّل المثبّت SQL Server أو أي ملف SQL. إعداد SQL الاختياري يستعمل قاعدة `MfgSystemDB` جديدة، ويتوقف إذا كان الاسم موجوداً بدلاً من تعديلها. تم جعل نص النسخ الاحتياطي الاختياري يرفض المهمة القائمة دون حذفها، وينشئ ملفات مؤرخة مع تحقق ولا يستبدل النسخة السابقة؛ الاحتفاظ التلقائي غير مفعّل.
5. **واجهة النسخ:** غُيّر المسار الافتراضي القديم إلى `C:\MfgSystem_Backups`، وأُضيف تنبيه ظاهر بأن شاشة النسخ الحالية مخصصة لـ SQL Server فقط ولا تدعم SQLite المحلية. تعيد الخدمة رسالة واضحة على SQLite بدلاً من إرسال أوامر SQL Server.
6. **اتساق الإصدار والحزمة:** تطابق `csproj` و`BuildInfo` والمثبت/المحدّث على `1.50.72`، وجرى تحديث تعليمات التنصيب وسجل التغييرات وفحوص الحزمة. احتُفظ بترميز ASCII ونهايات CRLF لملفات BAT. الفرع الحالي لا يتضمن أرشيف `DateERP_1.50.37_FULL_SOURCE.zip` القديم ولا ثنائيات؛ ويمنع `.gitignore` إضافة أرشيفات ومخرجات نشر وسجلات وSDK محلي لاحقاً.
7. **إصلاحات صياغية سابقة مثبتة في فرع العمل:** تعديل نص C# متعدد الأسطر، تعليق الاختبار، وبنية اختبار إقفال الخطة؛ لا تُعد هذه الإصلاحات بديلاً عن ترجمة Roslyn.

## ما لم يُختبر — مهم

- **لم يُشغّل `INSTALL-AND-RUN.bat` أو أي BAT/CMD/PowerShell على Windows.** لا يمكن إجراء اختبار CMD الحقيقي هنا.
- **لم يُنفّذ `dotnet build` أو `dotnet test` أو نشر WPF؛** .NET SDK/MSBuild غير متاحين في البيئة. لذلك لا يوجد ادعاء بأن النسخة بُنيت أو أن المثبّت نجح فعلياً على Windows.
- لم يُنشأ SQL Server فعلي ولم تُنفذ ملفات `.sql`؛ راجعها واختبرها في قاعدة اختبار قبل استخدامها.
- قد يحتاج NuGet إلى الإنترنت أو مخزن محلي كامل؛ وجود مثبت SDK لا يوفر حزم NuGet تلقائياً.
- لا تدعم شاشة النسخ الاحتياطي الحالية SQLite المحلي؛ يجب استخدام آلية نسخ ملفات SQLite مجرّبة مستقلة قبل تخزين بيانات إنتاجية مهمة.
