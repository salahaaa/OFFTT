# دليل النماذج والطباعة — 1.50.5 PrintPreview1

هذا التحديث يخص النماذج والمعاينة والطباعة. إصلاح منطق خطط الإنتاج مؤجل، ولا توجد تغييرات في جداول قاعدة البيانات أو قواعد المعالجة والحجز والصرف.

## الاستخدام

1. احفظ السند أو افتح سندًا محفوظًا؛ لا يلزم اعتماد المسودة لمعاينتها.
2. اضغط «طباعة» لعرض صفحات A4 الفعلية. النسخة من البيانات المحفوظة، لا من تعديلات الشاشة غير المحفوظة.
3. استخدم السابق/التالي أو التكبير و«ملاءمة العرض». هذه الأدوات لا تغير تقسيم الصفحات.
4. «طباعة…» يفتح اختيار الطابعة والورق ونطاق الصفحات. يحتفظ بتنسيق المستند ويصغّره نسبيًا إذا لزم ليناسب المساحة التي تسمح بها الطابعة.
5. «حفظ PDF مطابق» يحفظ الصفحات المعروضة نفسها. **PDF صور 300 DPI، وليس نصًا قابلًا للبحث أو النسخ**؛ لا تدّعِ أنه PDF/A أو موقع رقميًا.

### مواضع جديدة

- «أوامر تسليم الإنتاج»: أضيف زر معاينة السند المحفوظ.
- تفاصيل أمر الإنتاج: أضيف «تقرير التنفيذ والإقفال» لعرض الجلسات والتوقفات والمخرجات المسجلة.
- نافذة تشغيل اليوم: أضيف بيان الالتزامات المحفوظة. هذا ليس إثبات إنتاج ولا يصدر الأوامر المحددة في الشاشة.
- PDF متاح من معاينة الخطة وجميع النماذج المشتركة.

### بيانات مهمة

- تاريخ سند تسليم العميل من السجل، لا يوم الطباعة. وقت إنشاء النسخة ظاهر بصورة مستقلة.
- الاستلام يطبع نعم/لا/غير محدد وتاريخ المعالجة وحالتها لكل سطر. حلول الموعد دون تسجيل إتمام لا يُطبع «مكتملًا».
- الجودة تعرض قرارها وحالة اعتماد المحضر بصورة منفصلة. وحدات النتائج لا تُجمع معًا.
- القياسات المخبرية محفوظة، لكن حدود المعايير المطبوعة من التعريف الحالي لأن السجل لا يحتوي لقطة تاريخية لحدوده.
- التوقيعات الورقية لا تعتمد المستند أو تغير المخزون آليًا.

## تحديث Windows

الحزمة `DateERP_1.50.5_Print_Update_from_1.50.4.zip` **تحديث فروق فقط**؛ تحتاج مجلدًا كاملًا مستخرجًا من `DateERP_1.50.4_win-x64.zip` المسلّم سابقًا. لا تشغّلها كتطبيق مستقل، ولا تستخدم سكربتات Installer القديمة لهذا التحديث.

1. استخرج حزمة 1.50.4 كاملة وحزمة التحديث في مجلدين منفصلين. لا تستبدل ملفات المجلد القديم يدويًا.
2. من PowerShell، وفق سياسة جهازك المسموحة وبعد مراجعة مصدر السكربت:

```powershell
& 'C:\Updates\PrintUpdate\Apply-PrintUpdate.ps1' `
  -SourceFolder 'C:\Apps\DateERP_1.50.4_win-x64' `
  -Destination 'C:\Apps\DateERP_1.50.5_win-x64'
```

يجب أن يكون المجلد الهدف **غير موجود** وخارج المجلد القديم، وأن يكون مجلده الأب موجودًا. تُفحص بصمات ملفات الإصدار الأساسي، ثم تُنشأ نسخة جديدة وتُفحص؛ لا تشغيل تلقائي ولا وصول إلى قاعدة البيانات. عند عدم تطابق الملفات يتوقف التحديث بدل الدمج غير المضمون. لا تعطل سياسة PowerShell أو الحماية العامة؛ استعن بمسؤول الجهاز إن كانت السياسة تمنع تشغيل السكربت.

3. داخل المجلد الجديد، شغّل `Check-Print-WPF.cmd`. يولّد PDF وصورًا ببيانات اختبار مصطنعة؛ لا يفتح قاعدة تشغيل ولا يرسل وظائف طباعة. افحص العربية وفواصل الصفحات والتوقيعات بصريًا.
4. يمكن أيضًا تشغيل `Check-WPF.cmd` للتحقق من عناصر الاستلام، و`Verify-Release.ps1` وفق سياسة الجهاز لفحص ملفات المجلد.
5. اختبر التطبيق على قاعدة تجريبية وبنسخة احتياطية أولًا، ثم اطبع فعليًا نماذج طويلة وقصيرة وجرّب نطاق صفحات.

**المجلد الجديد لا يعزل قاعدة البيانات:** يظل التطبيق يقرأ `%LocalAppData%\DateERP\config.json` وقاعدة SQLite المحلية أو اتصال SQL Server المحفوظ. استخدم حساب Windows منفصلًا أو إعدادات اختبار مدارة. لا تشغل التطبيق على بيانات العمل دون نسخة احتياطية قابلة للاسترجاع؛ فالتطبيق يطبق تهيئة/ترحيل قاعدة البيانات عند بدء التشغيل كالسابق.

## حدود التحقق

بُني الحل ونُشرت ملفات Windows في بيئة Linux. لم تُشغّل WPF ولا السكربتات ولا طابعة فعلية هنا. يوجد 742 اختبارًا ناجحًا، منها 35 حالة جديدة لعقود الطباعة والبيانات والترقيم. فحص Windows البصري وقبول الطابعة مطلوبان قبل التعميم.

بصمات SHA-256 ليست توقيع ناشر رقميًا. التحديث لا يتضمن SQL Server ولا يغير صلاحيات التشغيل. احتفظ بالحزمة الأساسية والمجلد القديم والنسخة الاحتياطية؛ الرجوع للبرنامج القديم وحده ليس بديلًا عن استرجاع قاعدة البيانات إن طرأ عليها تغيير تشغيلي.
