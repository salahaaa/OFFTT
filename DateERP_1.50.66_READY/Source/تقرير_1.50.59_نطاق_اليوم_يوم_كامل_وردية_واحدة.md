# تقرير 1.50.59 — خيار يوم كامل / وردية واحدة قبل الإنزال

## سؤالك: هل يحدد الطاقة لكل يوم وينتقل لليوم التالي؟

**نعم، وأصبح الآن يجبرك تختار نطاق اليوم قبل أي إنزال.**

### ماذا حدث قبل 1.50.59؟
- كان النظام يحسب الطاقة من كل الورديات النشطة تلقائياً → لم تكن قادر تختار "وردية واحدة فقط".
- هذا كان يسبب خلطاً: يومك قد يكون 8 ساعات أو 16 ساعة حسب الورديات المفعلة، والنظام لا يسألك.

### ما الجديد في 1.50.59 (طلبك: يجبرك تختار قبل الإنزال)؟

في شاشة معالج التوزيع العادل أضفنا:

> **☑ نطاق اليوم: [ ] يوم كامل (كل الورديات النشطة) / [ ] وردية واحدة فقط**

- `UseFullDay = true (افتراضي)` → **يوم كامل** = مجموع كل الورديات النشطة.
  - مثال: عندك وردية نهار (8س) + ليل (8س) → اليوم = 16 ساعة إنتاج.
  - `dailyQuota = capacity_نهار + capacity_ليل`
  - التوزيع يملأ الأساسية أولاً ثم يفيض لنفس اليوم بالوردية الثانية مع وسم `ShiftName` في اسم الخطة.

- `UseFullDay = false` → **وردية واحدة فقط** = الأساسية فقط.
  - `dailyQuota = capacity_الأساسية فقط`
  - مفيد لو تعمل وردية واحدة اليوم أو تريد حصر التوزيع.

**هذا يحقق طلبك حرفياً:** "المفترض قبل التحديد ضروري يجبرك تختار وردية أو ورديتين أم يوم كامل قبل أي عملية إنزال كي يحسب حساب الطاقة" — صح، تم.

## مثالك: 4000 كرتون × 8 كجم يقفل اليوم وينتقل للعميل التالي

### الحساب:

```
يومك = 6000 كجم (مثال) + هدف يومي = 0 (أو رقم تكتبه)
العميل A: 4000 كرتون × 8 كجم = 32,000 كجم → أكبر من يوم كامل
```

**قبل 1.50.58:** كان النظام يوقف بعد أول عميل لأن اليوم امتلأ → لا ينتقل للعميل التالي بنفس اليوم.

**بعد 1.50.58 + 1.50.59:**

1. **سقف العميل/اليوم** (تحسين 3): `perCustCap = يوم / عدد العملاء × 1.5`
   - لو 3 عملاء ويوم 6000 كجم → سقف كل عميل = 6000/3*1.5 = 3000 كجم/يوم
   - طلب 32,000 كجم سيقسم: اليوم الأول يأخذ 3000 كجم (375 كرتون)، اليوم الثاني 3000، وهكذا.
   - **لن يأكل عميل واحد اليوم كله** — كل يوم سيكون فيه مساحة للعملاء الآخرين.

2. **انتقال لليوم التالي:**
   ```
   dayKgLeft = يوم - مستهلك
   slotHoursLeft = ساعات الوردية - مستهلك
   إذا dayKgLeft == 0 → اليوم مقفل → انتقل لليوم التالي
   إذا slotHoursLeft == 0 → انتقل للوردية التالية (نفس اليوم إذا UseFullDay=true)
   ```

3. **مثالك الثاني 8000×4 كجم = 32,000 كجم أيضاً:**
   - نفس السلوك، الفرق الوحيد هو عدد الكراتين مقابل الكجم.
   - `BatchKg = CartonQty × CartonKg` → الكجم هو الفيصل للطاقة، الكرتون للعد.

### جدول زمني مثال (UseFullDay=true, يوم=6000كجم, 2 عملاء):

| اليوم | الوردية | العميل | الكمية الموزعة | المتبقي من طلبه |
|-------|---------|--------|----------------|-----------------|
| 1/5 | نهار | A (4000×8) | 3000 كجم (سقف) | 29,000 |
| 1/5 | ليل | B (8000×4) | 3000 كجم (سقف) | 29,000 |
| 2/5 | نهار | A | 3000 | 26,000 |
| 2/5 | ليل | B | 3000 | 26,000 |

→ عادل، لا عميل يأكل اليوم.

## هل يتغير بوردية واحدة vs ورديتين؟

**نعم، جذرياً:**

| الإعداد | activeShifts | dailyQuota | سلوك التعبئة |
|---------|--------------|------------|--------------|
| ☑ يوم كامل | [نهار, ليل] | 6000+6000=12,000 كجم | يملأ نهار ثم ليل نفس اليوم |
| ☐ وردية واحدة | [نهار فقط] | 6000 كجم | يوم أقصر، ينتهي أسرع وينتقل لليوم التالي |

**متى تستخدم وردية واحدة؟**
- عندك نقص عمالة اليوم.
- تريد توزيع خفيف للتجربة.
- تريد حساب طاقة حقيقية ليوم واحد وردية.

**متى تستخدم يوم كامل؟**
- الوضع الطبيعي (مصنع يعمل ورديتين).
- تريد أقصى استغلال للمصنع.

## كيف يحدد الصنف التام؟

**§1.50.58 تحسين 1 — متوسط كل الأصناف:**

```
rate = (Σ جميع الأصناف kgPerHour) / (Σ جميع الأصناف count) / count(Finishing)
```

- قديماً: كان يأخذ أول صنف تام فقط → لو أول صنف بطيء، كل الحصة تنحسب بطيئة.
- الآن: متوسط كل الأصناف التامة المفعلة → أدق وأعدل.
- لو عندك صنف 8كجم بسرعة 100كجم/س وصنف 4كجم بسرعة 200كجم/س → المتوسط = 150كجم/س.
- ثم `slotHoursLeft -= batchKg / rate` → يحسب الساعات المستهلكة بدقة.

**AllowedFor:** يراعي تحويل Lot إلى صنف تام (Yield) عبر `RateOf(Finishing, PackUnit)`.
